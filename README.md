# ai-retro

> **English summary.** ai-retro reads your local Claude Code session logs, splits them into
> episodes (one user reply plus the agent turn it answers), classifies each episode as a
> correction, an instruction, a request or neutral, and finds what you keep repeating across
> conversations. For every recurring pattern it drafts a concrete edit for a project
> `CLAUDE.md`, the global `~/.claude/CLAUDE.md` or a skill's `SKILL.md`. The model is called
> through your own Claude Code subscription (`claude -p`); the database stays on your machine.
> Stage 1 status: pattern detection works, the correction classifier is not yet reliably
> measured. The tool and its docs are in Russian.

ai-retro разбирает локальные логи Claude Code и ищет, что вы повторяете агенту из беседы в
беседу. По каждому такому паттерну он пишет готовую правку для CLAUDE.md или SKILL.md, чтобы
не приходилось просить об одном и том же снова.

## Как это работает

```
файлы JSONL → записи → беседы → эпизоды → классификация → паттерны → предложения
                                                 ↓
                                        эталон → eval
```

1. **Файлы → записи → беседы.** `scan` читает `~/.claude/projects/**/*.jsonl` (только чтение)
   и собирает беседы: одна беседа может лежать в нескольких файлах, потому что rewind в Claude
   Code создаёт новый файл с копией истории (ADR 0001).
2. **Эпизоды.** Каждая реплика пользователя вместе с ответом агента — эпизод. Подмешанное
   харнессом (напоминания, результаты инструментов, встроенные команды вроде `/compact`)
   эпизодом не считается (ADR 0005, 0014). У эпизода бывают признаки: rewind, прерывание,
   отказ, вызов скилла.
3. **Классификация.** Модель ставит эпизоду категорию (поправка, инструкция, запрос,
   нейтрально) и суть — одну фразу о том, что пользователь поправил, уточнил или сообщил.
   Беседе ставится область (работа, учёба, …) по правилам путей.
4. **Эталон и eval.** Вы вручную размечаете выборку эпизодов (`label`), `eval` сравнивает с ней
   модель. Так видно, можно ли доверять категориям.
5. **Паттерны и предложения.** `report` группирует сути из разных бесед. Группа из 3+ эпизодов
   из 2+ бесед — паттерн. Для паттерна модель пишет предложение: файл, раздел, текст правки и
   обоснование. Файл выбирают правила, а не модель (ADR 0007).

Термины подробно, с примерами: [docs/concepts.md](docs/concepts.md).

## Требования

- Python 3.13 и [uv](https://docs.astral.sh/uv/).
- [Claude Code CLI](https://docs.claude.com/en/docs/claude-code) (`claude` в `PATH`) с
  выполненным входом по подписке. Модель вызывается так (ADR 0002):

  ```
  claude -p --safe-mode --system-prompt <промпт> --tools "" --model <модель> \
    --json-schema <схема> --output-format json --no-session-persistence
  ```

  `--safe-mode` отключает ваши CLAUDE.md, скиллы, хуки и MCP, чтобы они не влияли на
  классификацию. `--no-session-persistence` не даёт этим вызовам попасть в логи, которые
  потом читает `scan`. API-ключ не нужен; вызовы идут в счёт лимитов вашей подписки.
- Linux или macOS. На Windows не проверялось.

## Установка

```bash
git clone https://github.com/delawer33/ai-retro.git
cd ai-retro
uv sync
cp .env.example .env    # поправьте под себя, прежде всего AI_RETRO_DOMAIN_RULES
uv run ai-retro --help
```

Запускайте из каталога репозитория: оттуда читается `.env`, и там лежат миграции базы
(`migrations/`), которые применяются автоматически при каждой команде.

## Настройка

Все настройки — переменные окружения (или строки в `.env`), все необязательны.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `AI_RETRO_LOGS_DIR` | `~/.claude/projects` | Каталог логов Claude Code. Только чтение. |
| `AI_RETRO_DB_PATH` | `~/.local/share/ai-retro/ai-retro.db` | Локальная база SQLite: эпизоды, классификации, эталон, паттерны, предложения. |
| `AI_RETRO_MODEL` | `haiku` | Модель для `claude --model`. Смена модели меняет версию классификатора и требует переклассификации. |
| `AI_RETRO_THREADS` | `3` | Параллельных вызовов `claude`. Лимиты подписки общие с вашей работой, держите 2–4. |
| `AI_RETRO_CONTEXT_CHARS` | `2000` | Сколько символов ответа агента (с конца) и брошенной ветки (с начала) видит классификатор. |
| `AI_RETRO_DOMAIN_RULES` | `work=работа;projects=личные проекты;study=учёба` | Правила «префикс пути → область», см. ниже. Значение по умолчанию — пример, замените его. |
| `AI_RETRO_HOME` | `$HOME` | Каталог, от которого считаются префиксы в правилах областей. |
| `AI_RETRO_SKILLS_DIR` | `~/.claude/skills` | Корень глобальных скиллов (`<имя>/SKILL.md`). Скиллы проекта ищутся ещё в `<проект>/.claude/skills`. |

**Правила областей.** Формат `<префикс>=<область>`, правила через `;`. Префикс считается от
`AI_RETRO_HOME`; можно писать `~/x` или абсолютный путь. Сравнение идёт по целым компонентам
пути (`work` не совпадёт с `work-old`), при нескольких совпадениях побеждает самое длинное.
Области — только из списка: работа, личные проекты, учёба, идеи, философия, жизнь, иное.
Проект без правила получает «иное»; беседы без папки (scratch-беседы desktop-приложения)
получают область от модели по первой реплике. Пример:

```
AI_RETRO_DOMAIN_RULES=code/job=работа;code=личные проекты;uni=учёба;~/notes=идеи
```

## Команды

| Команда | Что делает | Флаги |
|---|---|---|
| `scan` | Разбирает логи в эпизоды и классифицирует новые. Повторный запуск не создаёт дублей и пересматривает уже сохранённые эпизоды по текущим правилам (ADR 0011). | `--since 12h\|1d\|2w` — только беседы с записями за это окно. |
| `label` | Разметка эталона в терминале: показывает признаки, контекст и реплику, вы жмёте `1`–`4` (категория), `s` (пропустить), `q` (выйти). Прогресс сохраняется. | `--extend` — добавить в выборку новые эпизоды; `--relabel` — повторно разметить вслепую 20 уже размеченных (для потолка). |
| `eval` | Качество классификатора на эталоне: матрица ошибок, precision/recall по категориям, бейзлайн на регулярках, потолок, стоп-критерий, расхождения с вами. | `--test` — test вместо dev; `--refresh` — классифицировать эталон заново. |
| `report` | Ищет паттерны и пишет markdown-отчёт с предложениями. Ничего, кроме файла отчёта, не меняет. | `--since 30d` — период; `--output путь.md` (по умолчанию `ai-retro-report.md`). |

`--since` принимает число и единицу: `h` (часы), `d` (дни), `w` (недели).

### Первая сессия

```bash
uv run ai-retro scan --since 30d     # печатает число вызовов модели, потом работает
uv run ai-retro report --since 30d   # → ai-retro-report.md
```

Этого достаточно, чтобы увидеть паттерны. Если хотите проверить классификатор на своих данных:

```bash
uv run ai-retro label                # 100 эпизодов; можно прерывать и продолжать
uv run ai-retro label --relabel      # 20 повторно, вслепую: ваш потолок согласия
uv run ai-retro eval                 # dev; правите промпт и смотрите снова
uv run ai-retro eval --test          # test — только подтвердить в конце
```

Сколько это стоит. За 30 дней активной работы получается 1 500–2 500 эпизодов, то есть
столько же вызовов `claude -p --model haiku`; первый `scan` идёт 1,5–2,5 часа и расходует
окно подписки. Следующие `scan` классифицируют только новые эпизоды. `report` делает один
вызов на группировку и по одному на каждый новый паттерн. Пример отчёта:
[docs/example-report.md](docs/example-report.md).

## Какие данные уходят с машины

- В модель уходят только тексты, нужные для конкретного вызова, и только через ваш
  `claude` по вашей подписке Anthropic: реплика эпизода, хвост предыдущего ответа агента и
  начало брошенной ветки (до `AI_RETRO_CONTEXT_CHARS` символов); для scratch-бесед — первая
  реплика (до 2000 символов); для отчёта — список сутей и до 5 реплик паттерна (до 300 символов
  каждая). Других сервисов и ключей нет.
- База лежит локально в `~/.local/share/ai-retro/` и содержит тексты эпизодов. Сделайте ей
  бэкап, если дорожите эталоном: git его не хранит (ADR 0003).
- Отчёт содержит цитаты ваших реплик и пути проектов. Не публикуйте его, не просмотрев.

## Статус и ограничения

Этап 1: `scan`, `label`, `eval`, `report`. Применения предложений ещё нет: команда `apply`
запланирована на этап 2, пока правку переносят в файл руками.

Цифры на данных автора (подробно: [docs/evaluation.md](docs/evaluation.md)):

- Эталон — 99 эпизодов (dev 69, test 30), поправок среди них всего 7.
- Поправка: precision/recall 0.29/0.50 на dev и 0.50/0.33 на test. Ориентир этапа
  (≥ 0.75 / ≥ 0.6) не достигнут.
- Потолок — согласие автора с самим собой при повторной разметке — 0.75.
- `report` за 30 дней нашёл 18 паттернов; на глаз около 12 из них настоящие.

Честный вывод: качество классификатора поправок пока не измерено — на 7 метках любая цифра
шумная. Работает поиск паттернов: он собирает сути всех трёх содержательных категорий, и
ошибка между «поправкой» и «уточняющим запросом» на него почти не влияет. Следующий шаг —
дорастить эталон до 25–30 поправок (`label --extend`) и перемерить.

Известные доработки:

- `eval` печатает округлённую разницу с бейзлайном, и строка «+15 п.п. (нужно ≥ 15)» может
  стоять рядом с «НЕТ».
- Предложения от прежней версии классификатора остаются в статусе «предложено» навсегда.
- Один и тот же текст, повторённый в одной беседе, раздувает размер паттерна.

Другие ограничения: формат логов Claude Code не документирован, и разбор может сломаться с
новой версией харнесса; temperature у `claude -p` не управляется, поэтому повторный прогон даёт
небольшой разброс; правка `src/ai_retro/classify/guide.md` или смена модели требует полной
переклассификации.

## Разработка

```bash
uv sync                                   # dev-зависимости включены
uv run pre-commit install                 # один раз на клон: ruff, mypy, gitleaks
uv run pytest -q
uv run ruff check . && uv run ruff format --check . && uv run mypy
```

- Pytest работает на синтетических логах и модели-заглушке; CI ничего не говорит о качестве
  разметки, его меряет `ai-retro eval` (ADR 0003).
- Схема базы меняется только миграциями Alembic в `migrations/`.
- Словарь домена — `CONTEXT.md`, решения — `docs/adr/`, заметки для агентов — `CLAUDE.md`.
- Промпт классификатора — `src/ai_retro/classify/guide.md`.
