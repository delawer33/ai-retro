# ai-retro

Находит, что вы раз за разом повторяете Claude Code, и пишет готовую правку для CLAUDE.md или SKILL.md.

> **In English.** ai-retro reads your local Claude Code logs, finds what you keep telling the agent across conversations, and drafts a concrete edit for `CLAUDE.md` or a skill's `SKILL.md`. Runs through your own subscription (`claude -p`), the database never leaves your machine. The tool and its docs are in Russian.

«Объясняй проще». «Не говори, что починил, пока не проверил». «Такие вопросы решай сам». Если вы ловите себя на том, что пишете это агенту в пятый раз, значит, правило должно лежать в файле, а не в вашей памяти. ai-retro разбирает логи бесед, группирует такие реплики в паттерны и для каждого предлагает текст правки, файл и раздел, куда её положить.

Вот что он находит. Фрагмент настоящего отчёта на логах автора, целиком в [docs/example-report.md](docs/example-report.md):

```markdown
### Непонятное объяснение

- эпизодов: 7, бесед: 6
- состав: 4 поправок, 1 инструкций, 2 уточняющих запросов
- примеры:
  - «с шага 5 я ничего не понимаю уже, объясни подробнее»
  - «непонятно ничего, маловато контекста /plain»
- предложение: `~/.claude/CLAUDE.md`, раздел «Стиль объяснений»
  > - Объясняй простыми словами. Если термин нужен, сразу расшифруй его одной фразой.
  > - Разбивай объяснение на короткие шаги, где каждый опирается на предыдущий.
  > - Начинай с конкретного примера или аналогии, и только потом переходи к абстракции.
```

## Быстрый старт

Нужны Python 3.13, [uv](https://docs.astral.sh/uv/) и [Claude Code CLI](https://docs.claude.com/en/docs/claude-code) (`claude` в `PATH`, вход по подписке выполнен). Linux или macOS, на Windows не проверялось.

```bash
git clone https://github.com/delawer33/ai-retro.git
cd ai-retro
uv sync
cp .env.example .env    # прежде всего поправьте AI_RETRO_DOMAIN_RULES, см. «Настройка»
uv run ai-retro scan --since 30d     # печатает число вызовов модели, потом работает
uv run ai-retro report --since 30d   # → ai-retro-report.md
```

Запускайте из каталога репозитория: оттуда читается `.env`, и там лежат миграции базы (`migrations/`), которые применяются сами при каждой команде.

> [!NOTE]
> **Сколько это стоит.** За 30 дней активной работы набирается 1 500–2 500 эпизодов, и столько же вызовов `claude -p --model haiku`. Первый `scan` идёт 1,5–2,5 часа и заметно расходует окно подписки. Следующие запуски классифицируют только новые эпизоды. `report` делает один вызов на группировку и по одному на каждый новый паттерн.

Этого хватает, чтобы увидеть паттерны. Проверить, насколько классификатору можно верить на ваших данных, можно отдельно, см. [Эталон и eval](#эталон-и-eval).

## Как это работает

```
файлы JSONL → записи → беседы → эпизоды → классификация → паттерны → предложения
                                                 ↓
                                        эталон → eval
```

1. **Беседы.** `scan` читает `~/.claude/projects/**/*.jsonl` только на чтение и собирает беседы. Одна беседа может лежать в нескольких файлах: rewind в Claude Code создаёт новый файл с копией истории.
2. **Эпизоды.** Реплика пользователя вместе с ответом агента на неё. Подмешанное харнессом (напоминания, результаты инструментов, встроенные команды вроде `/compact`) эпизодом не считается. У эпизода бывают признаки: rewind, прерывание, отказ, вызов скилла.
3. **Классификация.** Модель ставит эпизоду категорию (поправка, инструкция, запрос, нейтрально) и суть: одну фразу о том, что пользователь поправил, уточнил или сообщил. Беседе ставится область (работа, учёба, …) по правилам путей.
4. **Паттерны.** `report` группирует сути из разных бесед. Группа из 3+ эпизодов в 2+ беседах становится паттерном.
5. **Предложения.** Для паттерна модель пишет текст правки и обоснование. Файл и раздел выбирают правила, а не модель.

Термины с примерами: [docs/concepts.md](docs/concepts.md). Решения с мотивировкой: [docs/adr/](docs/adr/), в частности 0001 про rewind, 0005 и 0014 про границы эпизода, 0007 про выбор файла.

### Как вызывается модель

Без API-ключа, через ваш `claude` и в счёт лимитов вашей подписки ([ADR 0002](docs/adr/)):

```
claude -p --safe-mode --system-prompt <промпт> --tools "" --model <модель> \
  --json-schema <схема> --output-format json --no-session-persistence
```

- `--safe-mode` отключает ваши CLAUDE.md, скиллы, хуки и MCP, чтобы они не влияли на классификацию.
- `--no-session-persistence` не даёт этим вызовам попасть в логи, которые потом читает `scan`.

## Команды

### `scan`: разобрать логи и классифицировать новое

Повторный запуск не создаёт дублей и пересматривает уже сохранённые эпизоды по текущим правилам (ADR 0011).

- `--since 12h|1d|2w` — только беседы с записями за это окно.

### `report`: найти паттерны и написать отчёт

Ничего, кроме файла отчёта, не меняет.

- `--since 30d` — период.
- `--output путь.md` — куда писать, по умолчанию `ai-retro-report.md`.

### `label`: разметить эталон в терминале

Показывает признаки, контекст и реплику, вы жмёте `1`–`4` (категория), `s` (пропустить), `q` (выйти). Прогресс сохраняется, можно прерывать и продолжать.

- `--extend` — добавить в выборку новые эпизоды.
- `--relabel` — повторно разметить вслепую 20 уже размеченных, чтобы узнать свой потолок согласия.

### `eval`: качество классификатора на эталоне

Печатает матрицу ошибок, precision/recall по категориям, бейзлайн на регулярках, потолок, стоп-критерий и расхождения с вами.

- `--test` — test-срез вместо dev.
- `--refresh` — классифицировать эталон заново.

`--since` везде принимает число и единицу: `h` (часы), `d` (дни), `w` (недели).

### Эталон и eval

Если хотите знать, насколько классификатору можно доверять именно на ваших данных:

```bash
uv run ai-retro label                # 100 эпизодов; можно прерывать и продолжать
uv run ai-retro label --relabel      # 20 повторно, вслепую: ваш потолок согласия
uv run ai-retro eval                 # dev; правите промпт и смотрите снова
uv run ai-retro eval --test          # test — только подтвердить в конце
```

## Настройка

Все настройки — переменные окружения или строки в `.env`, все необязательны.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `AI_RETRO_LOGS_DIR` | `~/.claude/projects` | Каталог логов Claude Code, только чтение |
| `AI_RETRO_DB_PATH` | `~/.local/share/ai-retro/ai-retro.db` | Локальная база SQLite |
| `AI_RETRO_MODEL` | `haiku` | Модель для `claude --model` |
| `AI_RETRO_THREADS` | `3` | Параллельных вызовов `claude` |
| `AI_RETRO_CONTEXT_CHARS` | `2000` | Сколько символов контекста видит классификатор |
| `AI_RETRO_DOMAIN_RULES` | пример, замените | Правила «префикс пути → область» |
| `AI_RETRO_HOME` | `$HOME` | От чего считаются префиксы в правилах областей |
| `AI_RETRO_SKILLS_DIR` | `~/.claude/skills` | Корень глобальных скиллов (`<имя>/SKILL.md`) |

Что стоит знать:

- **Смена модели** меняет версию классификатора и требует переклассификации.
- **Потоки.** Лимиты подписки общие с вашей работой, держите 2–4.
- **Контекст.** `AI_RETRO_CONTEXT_CHARS` — это хвост ответа агента и начало брошенной ветки, которые видит классификатор.
- **Скиллы проекта** ищутся ещё и в `<проект>/.claude/skills`.

### Правила областей

Область нужна, чтобы отчёт различал рабочие и личные паттерны. Формат: `<префикс>=<область>`, правила через `;`.

```
AI_RETRO_DOMAIN_RULES=code/job=работа;code=личные проекты;uni=учёба;~/notes=идеи
```

- Префикс считается от `AI_RETRO_HOME`; можно писать `~/x` или абсолютный путь.
- Сравнение идёт по целым компонентам пути: `work` не совпадёт с `work-old`. При нескольких совпадениях побеждает самое длинное.
- Области только из списка: работа, личные проекты, учёба, идеи, философия, жизнь, иное.
- Проект без правила получает «иное». Беседы без папки (scratch-беседы desktop-приложения) получают область от модели по первой реплике.

## Что уходит с машины

Других сервисов и ключей, кроме вашего `claude`, нет. В модель уходит только то, что нужно для конкретного вызова:

- **На классификацию:** реплика эпизода, хвост предыдущего ответа агента и начало брошенной ветки, до `AI_RETRO_CONTEXT_CHARS` символов.
- **На определение области scratch-беседы:** первая реплика, до 2000 символов.
- **На отчёт:** список сутей и до 5 реплик паттерна, до 300 символов каждая.

> [!WARNING]
> База в `~/.local/share/ai-retro/` содержит тексты эпизодов, а отчёт — цитаты ваших реплик и пути проектов. Не публикуйте отчёт, не просмотрев. Базе сделайте бэкап, если дорожите эталоном: git её не хранит (ADR 0003).

## Статус и ограничения

**Этап 1.** Поиск паттернов работает, и это главное: он собирает сути всех трёх содержательных категорий, и ошибка между «поправкой» и «уточняющим запросом» на него почти не влияет. **Качество классификатора поправок пока не измерено:** в эталоне всего 7 поправок, на такой выборке любая цифра шумная. Команды `apply` ещё нет, правку переносят в файл руками; она запланирована на этап 2.

Цифры на данных автора, подробно в [docs/evaluation.md](docs/evaluation.md):

| Что | Значение |
|---|---|
| Эталон | 99 эпизодов (dev 69, test 30), поправок 7 |
| Поправка, precision/recall | 0.29/0.50 на dev, 0.50/0.33 на test |
| Ориентир этапа | ≥ 0.75 / ≥ 0.6, не достигнут |
| Потолок (согласие автора с самим собой) | 0.75 |
| `report` за 30 дней | 18 паттернов, на глаз около 12 настоящих |

Следующий шаг: дорастить эталон до 25–30 поправок (`label --extend`) и перемерить.

Известные доработки:

- `eval` печатает округлённую разницу с бейзлайном, и строка «+15 п.п. (нужно ≥ 15)» может стоять рядом с «НЕТ».
- Предложения от прежней версии классификатора остаются в статусе «предложено» навсегда.
- Один и тот же текст, повторённый в одной беседе, раздувает размер паттерна.

Ограничения по природе инструмента:

- Формат логов Claude Code не документирован, разбор может сломаться с новой версией харнесса.
- Temperature у `claude -p` не управляется, повторный прогон даёт небольшой разброс.
- Правка `src/ai_retro/classify/guide.md` или смена модели требует полной переклассификации.

## Для разработки

```bash
uv sync                                   # dev-зависимости включены
uv run pre-commit install                 # один раз на клон: ruff, mypy, gitleaks
uv run pytest -q
uv run ruff check . && uv run ruff format --check . && uv run mypy
```

- **Тесты** работают на синтетических логах и модели-заглушке. CI ничего не говорит о качестве разметки, его меряет `ai-retro eval` (ADR 0003).
- **Схема базы** меняется только миграциями Alembic в `migrations/`.
- **Промпт классификатора** — `src/ai_retro/classify/guide.md`.
- **Где что лежит:** словарь домена в `CONTEXT.md`, решения в `docs/adr/`, заметки для агентов в `CLAUDE.md`.
