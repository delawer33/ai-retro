# Эпизодом считается только то, что пользователь написал сам; остальное отсеивается по записи и по блоку

В логах реплики пользователя перемешаны с подмешанным харнессом: напоминания, уведомления задач,
локальные команды, отказы automode и правил. Нужно решить, что считать репликой и как отсеивать.

Реплика — только запись с origin human (или без origin). Блоки текста чистятся по одному
публичной функцией `clean_reply` стыка «записи → эпизоды»: `<system-reminder>` и
`<artifact-view-context>` (контекст открытого артефакта) убираются,
`<command-*>` становится «/имя аргументы», `<pasted_content>` — «[вставка N символов]»,
уведомления задач, вывод локальных команд и compact-сводка реплики не дают. Остальные блоки той
же записи остаются. Функция публичная, чтобы её мог вызвать доменный сервис для scratch-бесед.
Отказ пользователя (с причиной или без) — признак, а отказы automode и правил — нет. Прерывание —
признак `прерывание`. Слэш-команда получает категорию «вызов скилла» без модели (до ADR 0004
реализации).

Проект записи — путь родительского репозитория: из cwd отрезается `/.claude/worktrees/…`. Запись
без cwd берёт путь из cwd другой записи с тем же именем каталога лога (после отрезания
`--claude-worktrees-…`), в том числе родительского проекта; если таких нет, имя каталога грубо
декодируется заменой «-» на «/». Dash-кодировка без потерь не декодируется, поэтому последний
случай ошибается на путях с дефисами и точками; он редок (записи без cwd — единицы).

Альтернатива — проверять префикс у склеенного текста записи или кодировать cwd в форму имени
каталога. Первое теряет ответ пользователя, если напоминание идёт первым блоком (в реальных
логах около 41 такой записи); второе ломает правила областей, которые работают с путями.

## Consequences

- Число эпизодов на реальных логах (около 2400 на 30 дней) проверяет QA вручную.
- Проект в базе всегда в форме пути; правила областей и `is_scratch` работают на нём как раньше.
- Запись без cwd в каталоге, где ни одной записи с cwd нет, может получить неточный проект.
