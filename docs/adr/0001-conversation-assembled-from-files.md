# Беседа собирается из нескольких файлов, эпизод идентифицируется uuid реплики

Rewind в desktop-приложении Claude Code не ветвит JSONL-файл, а создаёт новый файл сессии с
копией истории до точки отката. За месяц таких ответвлений ~160, и 2 027 реплик пользователя
лежат одновременно в нескольких файлах. Развилки внутри одного файла почти всегда — параллельные
tool calls, а не rewind.

Беседа восстанавливается как дерево по общим `uuid` реплик во всех файлах проекта; эпизод
идентифицируется `uuid` реплики, а не парой «файл + позиция». Rewind — это файл, который делит
префикс с более ранним и дальше расходится с ним; ветка более раннего файла после точки
расхождения — брошенная. Рассматривали «файл = сессия», как в исходной спеке: проще, но каждая
скопированная реплика считалась бы заново (частоты паттернов раздуваются в разы), а сам rewind
был бы не виден.

## Consequences

- Эпизоды дедуплицируются по `uuid`; повторный `scan` и копии истории не создают дублей.
- `scan` не может обрабатывать файл в изоляции: чтобы понять, ответвление ли он, нужны остальные
  файлы проекта.
- Мы зависим от недокументированного поведения харнесса: если формат rewind поменяется, детектор
  молча перестанет его видеть. Нужен тест на фикстуре реального ответвления.
