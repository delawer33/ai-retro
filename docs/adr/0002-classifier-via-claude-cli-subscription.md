# Классификатор вызывает модель через `claude -p` по подписке, в изолированном режиме

Классификатору нужна модель уровня Haiku на ~2 400 эпизодов в месяц плюс итерации на эталоне.
Хотелось не заводить нового провайдера и ключи: сессии и так проходят через Anthropic, и
отправлять их реселлеру или агрегатору открытых моделей — новое раскрытие. Локальная модель на
этой машине (CPU, без GPU) делает итерацию на эталоне за 40 минут – 2 часа вместо минут.

Модель вызывается через headless Claude Code по подписке пользователя, в одном месте кода и
строго так:

```
claude -p --safe-mode --system-prompt <гайд> --tools "" --model <из Settings>
  --json-schema <схема> --output-format json --no-session-persistence
```

`--safe-mode` отключает CLAUDE.md, скиллы, плагины, хуки и MCP — иначе правки, которые
предлагает сам тул, меняли бы поведение классификатора и мерило плыло бы. `--system-prompt`
заменяет системный промпт харнесса целиком. `--no-session-persistence` не даёт вызовам
классификатора попасть в `~/.claude/projects`, откуда `scan` их бы и разметил. `--bare` не
подходит: он не читает OAuth подписки. Рассматривали Anthropic API через SDK: детерминированнее
(temperature) и быстрее, но это ключ, оплата и отдельный биллинг ради того же провайдера.

## Consequences

- Вызов модели — функция «промпт → ответ», передаваемая сервисам явно; замена на SDK или
  локальную модель не трогает классификатор, а эталон показывает, изменилось ли качество.
- Каждый прогон evals записывает рядом с метриками версию `claude` и модель: поведение флагов
  может меняться между версиями.
- Temperature не управляется; разброс измеряется повторным прогоном эталона, разница между
  версиями меньше разброса значимой не считается.
- Лимиты подписки общие с рабочими сессиями: `scan` идёт порциями, в 2–4 потока.
- Страховка от петли на случай, если `--no-session-persistence` перестанет работать: системный
  промпт классификатора содержит маркер, и `scan` пропускает беседы, где он встречается.
