# Ответ не по схеме пропускается после повтора, невозможный вызов прерывает скан

На QA реального скана (~1400 вызовов) один ответ модели текстом вместо структуры дважды оборвал
весь `scan`: повтора и пропуска не было. Нужен делитель между сбоями, которые случаются на одном
эпизоде, и сбоями, которые повторятся на каждом вызове.

Делитель — тип исключения. `ClassifierSchemaError` (подкласс `ModelCallError`) — ответ не по
схеме или неизвестная категория: один повтор того же вызова, затем эпизод остаётся без
классификации и `scan` идёт дальше, в конце печатает «Не классифицировано: N». Всё остальное
(`UnrecognizedModelError`, `ClaudeNotFoundError`, таймаут, лимит, авторизация, ненулевой код
`claude`) по-прежнему прерывает скан: оно повторится на следующем вызове, пропуск лишь сожжёт
подписку. Альтернатива — пропускать любую ошибку после N подряд сбоев; проиграла сложностью и
тем, что тихо тратит вызовы до порога. Эпизоды без классификации следующий `scan` берёт снова
сам (он выбирает эпизоды без записи для текущей версии классификатора).

## Consequences

- Повтор и пропуск живут в `classify_many`, поэтому касаются и `evals`: там пропуск искажает
  метрики, и `evals` падает `ClassifierSchemaError` после сохранения полученного.
- Правка `guide.md` (объяснение плейсхолдера «[вставка N символов]») меняет версию классификатора.
