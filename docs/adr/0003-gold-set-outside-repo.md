# Эталон живёт в локальной базе, а не в репозитории; в CI — только синтетика

Эталон состоит из реальных реплик пользователя и ответов агента: рабочие разговоры, код,
вставки с личными данными. Естественный ход — положить его в `tests/` как фикстуру и гонять в
pytest; но тогда личные тексты навсегда остаются в истории git и на GitHub, а в CI проверка
всё равно не работает — там нет подписки `claude` (ADR 0002).

Эталон хранится в той же локальной SQLite, что и эпизоды (`~/.local/share/ai-retro/`, путь в
`Settings`): ссылка на эпизод по `uuid`, метка, дата разметки. Качество классификатора меряет
команда `ai-retro eval`, а не pytest; её результаты (git sha промпта, модель, версия `claude`,
метрики) пишутся туда же. В репозитории — гайд по разметке, промпт и JSON-схема: это код
классификатора. Pytest проверяет парсинг, сборку бесед и подсчёт метрик на выдуманных JSONL.

## Consequences

- База хранит текст эпизода и его контекст (то, что видит классификатор), а не ссылку на JSONL:
  Claude Code чистит старые транскрипты, а эталону, переразметке и трендам нужна история
  дольше этого срока.
- Потеря базы = потеря эталона и истории: нужен бэкап этого файла, git его не заменяет.
- Зелёный CI не говорит ничего о качестве разметки; перед мержем изменений промпта или модели
  `ai-retro eval` запускается вручную.
- Синтетические фикстуры должны воспроизводить реальные случаи (rewind-ответвление, прерывание,
  отказ, вставка) — они пишутся по образцам из настоящих логов, без их текста.
