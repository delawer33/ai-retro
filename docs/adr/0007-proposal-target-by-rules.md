# Цель предложения выбирают правила, текст правки пишет модель

Предложение (`CONTEXT.md`) нужно нацелить на файл: CLAUDE.md проекта, глобальный CLAUDE.md или
SKILL.md. Выбор можно отдать модели вместе с текстом, но тогда его не проверить тестом, а ошибка
цели (правка проекта в глобальный файл) тихо портит чужие беседы.

Цель выбирает чистая функция `choose_target` по эпизодам паттерна: если с одним скиллом связано
больше половины эпизодов (вызван им или идёт в беседе после его вызова, ADR 0004) — SKILL.md
этого скилла; иначе беседы одного не-scratch проекта — CLAUDE.md проекта; иначе (разные проекты
или scratch) — глобальный `~/.claude/CLAUDE.md`. Модель получает цель в промпте и пишет раздел,
текст и обоснование. Единственное решение модели о цели — «новый скилл»: тогда у предложения
нет файла (`target_file` пуст), оно остаётся текстом. Путь SKILL.md строится по соглашению
`~/.claude/skills/<имя>/SKILL.md`, наличие файла не проверяется: скиллы плагинов и проектные
лежат в других местах, а `apply` на этапе 2 всё равно проверит файл перед записью.

Предложение сохраняется со статусом `proposed` в том же виде, что в отчёте. Повторный `report`
не генерирует и не дублирует предложение для паттерна с тем же набором эпизодов: берётся
сохранённое, иначе применяемый текст разошёлся бы с тем, что пользователь видел. Рассматривали
пустой `target_file` против nullable-колонки: миграция ради пустого значения не окупается.

## Consequences

- Правила цели покрыты тестами без модели; поменять их — правка одной функции.
- Один вызов модели на каждый новый паттерн сверх вызова группировки.
- Паттерн, который изменился (другой набор эпизодов), получает новое предложение; старое остаётся
  в базе до решения пользователя.
- Для SKILL.md несуществующего пути `apply` должен отказать, а не создавать файл.
