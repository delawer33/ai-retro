# Скилл — это то, у чего на диске есть SKILL.md

ADR 0004 поставил признак «вызов скилла» на любую слэш-команду. В базе после настоящего `scan`
оказалось: compact 24, model 6, login 2 — встроенные команды Claude Code, не скиллы. `report`
привязывал к ним поправки и предлагал цель `~/.claude/skills/compact/SKILL.md`, которого нет.

`scan` ставит признак (и `skill`) только если `<имя>/SKILL.md` лежит в глобальном корне скиллов
(`AI_RETRO_SKILLS_DIR`, по умолчанию `~/.claude/skills`) или в `<проект>/.claude/skills`. Иначе
реплика обычная: без признака, с пустым `skill`, и классифицируется целиком, как любая другая.
`report` повторяет проверку при сборке паттернов: скилл эпизода (свой или предшествующий в
беседе), чей SKILL.md сейчас не найден, считается отсутствующим, и цель выбирается дальше по
ADR 0007 — CLAUDE.md проекта или глобальный. Так цель всегда существующий файл, а старые строки
базы со встроенными командами не требуют миграции. Рассматривали список встроенных команд в коде:
он устаревает с каждым релизом Claude Code и не знает про скиллы плагинов и проектов.

## Consequences

- Скиллы плагинов (лежат вне этих корней) признака не получают, пока корень не задан; цена —
  пропущенный сигнал, а не ложная цель.
- Результат `scan` зависит от состояния диска на момент запуска; уже сохранённые эпизоды не
  переразмечаются (признак у встроенных команд в старой базе уберёт новый `scan` с чистой базой).
- Удалённый позже скилл исчезает из целей `report`, хотя в базе остаётся.
- Дополняет ADR 0004 и 0007: цель-скилл в `report` — путь того SKILL.md, который реально найден
  (сначала `<проект>/.claude/skills` проекта эпизода, затем `AI_RETRO_SKILLS_DIR`), а не путь по
  соглашению. Домашний каталог печатается как `~/…`, остальное абсолютным путём.
