# Актуальная классификация эпизода — последняя вставленная строка

В `classifications` у эпизода бывает несколько строк: после смены `classifier_version` и после
`eval --refresh`. `report` и `label` джойнили все строки и считали такие эпизоды дважды.

Актуальная классификация — строка с наибольшим `id` (функция `latest_classifications` в срезе
`classify`; её используют `report`, `eval`, `label`). Таблица только дополняется, поэтому `id`
растёт вместе со временем вставки; отдельный `created_at` не нужен, миграции нет. Колонку
`created_at` с тай-брейком по `id` мы отвергли: она дублирует порядок `id` и требует заполнять
старые строки выдуманным временем.

`report` и `eval` ищут актуальную строку среди строк текущей версии классификатора, `label` — среди
всех версий. `eval --refresh` удаляет прежнюю строку той же версии перед вставкой новой, так что
на пару (эпизод, версия) строка одна.

## Consequences

- Повторный `eval --refresh` не увеличивает число строк.
- Строки старых версий остаются в базе, но ни в отчёт, ни в метрики не попадают.
- Если когда-нибудь строки начнут вставляться не по порядку (импорт, слияние баз), порядок по
  `id` придётся заменить на временную метку.
