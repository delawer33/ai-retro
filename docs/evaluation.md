# Оценка качества

Категории ставит модель, и им нельзя верить на слово. Мерило — эталон: эпизоды, которые вы
разметили сами. Эталон живёт только в локальной базе, в репозиторий не попадает: это ваши
реальные реплики (ADR 0003). Поэтому CI качество разметки не проверяет, его меряет команда
`ai-retro eval`.

## Как собирается эталон

`ai-retro label` при первом запуске берёт из базы 100 классифицированных эпизодов по трём
стратам:

| Страта | Доля | Зачем |
|---|---|---|
| с признаками (прерывание, отказ, rewind, вызов скилла) | 40% | За прерыванием и отказом чаще всего идёт поправка; они берутся первыми, вызов скилла — последним. |
| модель сказала «не нейтрально» | 40% | Проверить, что модель не выдумывает поправки и инструкции. |
| модель сказала «нейтрально» | 20% | Проверить, что модель не пропускает их. |

Внутри страты эпизоды берутся по кругу по проектам и не больше 3 из одной беседы, чтобы одна
длинная беседа не заняла эталон. Порядок детерминированный (хеш uuid), поэтому выборка
воспроизводится.

Разбиение: 30% выборки по хешу uuid — **test**, остальное — **dev**. По dev правят промпт
(`src/ai_retro/classify/guide.md`) и смотрят расхождения; test запускают в конце, только
чтобы подтвердить результат. Метку модели при разметке вы не видите.

`label --extend` добавляет в выборку новые эпизоды по тем же правилам. Исходная метка никогда
не переписывается.

**Повторная разметка вслепую.** `label --relabel` показывает 20 уже размеченных эпизодов ещё
раз, без вашей прошлой метки. Доля совпадений — **потолок**: выше согласия человека с самим
собой требовать от модели бессмысленно.

## Что печатает `eval`

`eval` берёт сохранённые классификации текущей версии классификатора и вызывает модель только
для эпизодов эталона без них (ADR 0008); `--refresh` классифицирует эталон заново. Версия
классификатора — sha промпта плюс модель, поэтому после правки `guide.md` эталон
переклассифицируется сам.

Вывод по порядку:

1. **Матрица ошибок**: строки — ваша метка, столбцы — метка модели.
2. **Модель**: precision и recall по каждой категории, сколько таких в эталоне и сколько
   предсказано; в скобках — изменение к прошлому прогону того же split.
3. **Бейзлайн**: те же метрики у регулярки по словам-маркерам («не так», «я же просил»,
   «зачем ты», …) плюс признаки прерывания и отказа. Без модели.
4. **Потолок**: согласие с собой по парам из `label --relabel`.
5. **Стоп-критерий этапа 1** (ниже).
6. **Расхождения с человеком**: uuid, обе метки и начало реплики.

## Стоп-критерий этапа 1

| Проверка | Условие | Если не выполнено |
|---|---|---|
| потолок | Согласие с собой ≥ 0.75. | Категории размыты, чинить определения. |
| бейзлайн | Precision поправок у модели выше, чем у регулярки, на ≥ 15 п.п. | Модель не окупается, категории может ставить регулярка. |
| ориентир | Precision поправок ≥ min(0.8, потолок), recall ≥ 0.6. | Править промпт по расхождениям на dev. |
| паттерны | Не больше 2 фальшивых в топ-10 отчёта. | Проверяется глазами по отчёту, `eval` это не считает. |

## Текущие цифры

На данных автора, 30 дней логов, модель `haiku`. Эталон — 99 эпизодов: dev 69, test 30.
Поправок в нём всего 7 (4 в dev, 3 в test).

| | dev | test |
|---|---|---|
| precision поправок, модель | 0.29 | 0.50 |
| recall поправок, модель | 0.50 | 0.33 |
| precision поправок, регулярка | 0.14 | 0.20 |
| потолок (20 пар) | 0.75 | 0.75 |

Что это значит:

- **Классификатор поправок не измерен.** На 4 и 3 примерах одна метка двигает precision и
  recall на десятки пунктов: после того как определение поправки сузили (ADR 0016), recall
  поправок на test упал с 1.00 до 0.33, то есть с 3 из 3 до 1 из 3. Ориентир не достигнут, но
  и провалом это назвать нельзя — данных нет.
- **Потолок ровно на пороге.** Автор сам расходится с собой в каждом четвёртом эпизоде;
  граница между поправкой и уточняющим запросом и для человека нечёткая.
- **Поиск паттернов работает.** `report` за те же 30 дней дал 18 паттернов, на глаз около 12
  из них настоящие повторы, которые стоит превратить в правило. Паттерны собираются из сутей
  поправок, инструкций и уточняющих запросов вместе, поэтому путаница между этими категориями
  на них почти не влияет. Пример: [example-report.md](example-report.md).

Следующий шаг: дорастить эталон до 25–30 поправок через `label --extend` (страта «с признаками»
теперь первой берёт прерывания и отказы) и перемерить dev и test.
